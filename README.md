# blind_aid

라즈베리파이 5 + 카메라로 **보행 신호등 · 점자블록 · 전방 장애물**을 인식해
음성으로 안내하는 시각장애인 보행 보조 장치.

> ⚠️ **연구/시제품 단계입니다.** 이 장치만 믿고 횡단하지 마십시오.
> 흰지팡이·음향신호기와 병행하는 것을 전제로 설계했습니다.

---

## 기능

| 기능 | 방식 | 학습 |
|---|---|---|
| 보행 신호등 (적/녹/꺼짐) | YOLO11n 검출 → MobileNetV3-Small 크롭 분류 → 5프레임 투표 | AI Hub 056 |
| 점자블록 추적 | LAB `b*` 채널 + 최소외접사각형 | 규칙 |
| 장애물 + 거리 | COCO 사전학습 YOLO11n + ByteTrack, bbox 높이 단안 거리추정 | 사전학습 |
| 조도 프로파일 | BH1750 센서, 없으면 카메라 gain 프록시 | 규칙 |
| 음성 안내 | 우선순위 큐 + 쿨다운 (print / espeak-ng / wav) | — |

## 안전 설계 원칙

오탐의 비용이 비대칭입니다. "녹색인데 인식 못 함"은 불편이지만,
**"적색인데 녹색이라고 안내"는 사고**입니다. 그래서:

- **기본 동작은 침묵입니다.** 확신이 없으면 안내하지 않습니다.
- **단일 프레임으로 발화하지 않습니다.** 5프레임 창에서 3표 이상일 때만 확정합니다.
- **"모름"을 "적색 아님"으로 바꾸지 않습니다.** 분류기 확신이 낮으면 그대로 둡니다.
- **야간에는 신호 판정을 하지 않습니다.** 오판보다 "확인할 수 없습니다"가 안전합니다.
- **명령형 문구를 쓰지 않습니다.** "건너세요"가 아니라 "녹색불입니다".
- **임계값을 성능을 이유로 완화하지 않습니다.** 완화는 언제나 안전 마진의 소모입니다.

## 파이프라인

```
카메라 (Picamera2 듀얼 스트림)
 ├─ MAIN 1920x1080 ─┬─▶ 신호등: YOLO(함체 검출) → 크롭 → CNN(적/녹/꺼짐) → 5프레임 투표
 │                  └─▶ 점자블록: 하단 ROI → LAB b* → 방향/편차
 └─ LORES 416x416  ──▶ 장애물: YOLO(COCO) + ByteTrack → 거리 → 접근속도
     BH1750 / gain ──▶ 조도 프로파일 → 야간엔 신호 판정 중단
```

초기 프로토타입은 HSV 임계값만으로 판정했고, **신호등 옆 빨간 간판**을 적색등으로
오인해 실패했습니다. 색은 검출 근거가 아니라 확인용 속성입니다. 지금은 YOLO가 함체를
형태로 찾고 그 안에서만 분류기가 상태를 봅니다. 검출 학습 시 `car_light` / `traffic_sign` 을
hard negative 클래스로 함께 넣어, 그 실패 케이스를 모델이 직접 배우게 했습니다.

## 성능

### 데이터셋 실측 (AI Hub 056 val)

| 검출기 (IoU 0.5, conf 0.25, imgsz 1024) | 재현율 |
|---|---:|
| 보행등 높이 15px 미만 | 0.50 |
| 15–30px | 0.78–0.82 |
| 30px 이상 | 0.89–0.90 |

15px 미만은 사람 눈으로도 판독이 불가능한 크기라 `SIGNAL_MIN_BOX_H` 로 분류에서 제외합니다.

분류기 (val 1,993개, 원본 이미지 단위 분리) — macro F1 **0.926**,
**red → green 오분류 0.29%** (2/682). 램프 가림 실험에서 적색을 가리면 red만,
녹색을 가리면 green만 선택적으로 붕괴 → 색이 아니라 **함체 내 점등 위치**를 보고 있음을 확인.

> ⚠️ 위 수치는 전부 **차량 블랙박스 시점** 데이터 기준입니다.

### 라즈베리파이 5 실기 관측 (단발)

| 항목 | 값 |
|---|---|
| 백엔드 | NCNN, `SIGNAL_DET_IMGSZ = 1024` |
| 검출 거리 / 신뢰도 | 12 m / 0.85 이상 |
| 신호색 판정 | 정확 |
| 전체 루프 | 평균 **2.4 FPS** |

보행자 눈높이에서 12m 함체를 잡고 색까지 맞혔다는 것이 핵심입니다. 학습 데이터가
차량 시점뿐이라 구도 차이가 가장 큰 불확실성이었는데, 그 방향의 첫 실기 근거입니다.

> 0.85는 정확도가 아니라 **검출기의 신뢰도 점수**입니다. 재현율과 오검출률은
> 이 관측으로 측정하지 않았습니다. 1회 관측이며, 라벨이 붙은 녹화 fixture 로 다시 측정합니다.

### 튜닝 기준 — 처리량이 아닌 안내 지연

가속기 없이 CPU 로만 추론하므로 프레임률에는 한계가 있습니다. 다만 사용자가 체감하는 것은
초당 프레임 수가 아니라 **신호가 바뀐 뒤 안내가 나오기까지의 지연**이라, 그 축으로 설정을 잡았습니다.

`SignalVoter` 는 확정에 판정 3회가 필요하므로, 지연을 지배하는 것은 판정 주기입니다.

| 설정 | 확정 지연 |
|---|---:|
| `SIGNAL_INTERVAL = 3` | 3.75 초 |
| `SIGNAL_INTERVAL = 1` (실기 적용) | **1.25 초** |

`SIGNAL_INTERVAL = 1`, `DETECT_INTERVAL = 3` 으로 운용합니다. 신호 판정을 매 프레임 수행하고
장애물 검출 주기를 늦춘 구성으로, 전체 프레임률을 조금 내주는 대신 안내 지연을 3분의 1로 줄입니다.
보행 속도에서 장애물은 초당 3~5회 확인으로 충분합니다.

지연을 더 줄일 여지는 추론 비용 쪽(입력 크기, 모델 크기)에 있습니다.
**투표·확신 임계값을 낮추는 방식은 쓰지 않습니다.** 그것은 속도 개선이 아니라 안전 마진의 소모입니다.

## 설치 및 실행

Raspberry Pi 5 (8GB) + OV5647 CSI 카메라에서 동작하며, Python 3.11 이상이 필요합니다.
가속기 없이 CPU 로 추론하고, BH1750 조도센서는 선택 사항입니다.

```bash
# 카메라 / 음성 — apt 로 설치 (pip 설치 시 picamera2 정상 동작 불가)
sudo apt install -y python3-picamera2 python3-libcamera espeak-ng alsa-utils
pip install -r requirements.txt
pip install onnxruntime          # 분류기 추론 — 파이에 torch 를 두지 않기 위한 경로
```

```bash
python main.py --source sample.mp4 --view --tts print   # PC, 동영상
python main.py --source pi --tts espeak                 # 실기
python main.py --source pi --signal-backend rule        # 모델 문제 시 규칙 기반(레거시)
```

모델 로드에 실패하면 경고를 출력하고 자동으로 규칙 기반으로 전환됩니다.

### 초기 점검 순서

```bash
python selftest.py       # 하드웨어 없이 로직 검증 — 25/25 통과해야 정상
python check_camera.py   # 카메라 진단
python bench_pi.py       # .pt vs NCNN 속도 비교
python calibrate.py      # FOCAL_PX 실측 ★ 필수
```

`calibrate.py` 를 건너뛰지 마십시오. `config.FOCAL_PX = 520` 은 측정값이 아니라
placeholder 이며, 이 값으로 나오는 "3미터 앞 장애물"은 그럴듯하지만 틀린 숫자입니다.

**카메라 설정에서 AWB와 AE는 반드시 꺼야 합니다.** 자동 화이트밸런스는 큰 빨간 간판이
들어오면 전체 색온도를 이동시켜 녹색 신호의 색조를 망가뜨립니다(프로토타입 실패의 직접 원인).
신호등은 발광체라 노출을 낮게 고정해야 점등 램프만 분리됩니다. 또한 picamera2의 `RGB888` 은
이름과 달리 BGR 로 들어오는 경우가 있어, **뒤집혀 있으면 빨간불과 초록불이 서로 바뀝니다** —
`check_camera.py` 의 채널 순서 확인이 가장 중요한 이유입니다.

## 설정

현장 튜닝 상수는 전부 [config.py](config.py) 한 곳에 있습니다.

| 상수 | 의미 |
|---|---|
| `FOCAL_PX` | 거리 추정 기준값. `calibrate.py` 실측치로 대체 |
| `SIGNAL_DET_IMGSZ` | 검출 입력 크기. 640 으로 낮추면 속도 향상, 검출률 하락 |
| `SIGNAL_INTERVAL` | N프레임마다 1회 신호 판정. 실기 적용값 1 |
| `DETECT_INTERVAL` | N프레임마다 1회 장애물 검출. 실기 적용값 3 |
| `COOLDOWN_S` | 안내 종류별 최소 재발화 간격 |

## 알려진 한계

- **학습 데이터가 차량 주행 시점입니다.** 보행자 눈높이 성능은 위 단발 관측 외에 측정하지
  않았습니다. 실사용 전 직접 촬영 데이터로 파인튜닝합니다.
- **실기 처리량이 낮습니다.** 가속기 없는 CPU 추론이라 2.4 FPS 이며, 안내 지연은
  `SIGNAL_INTERVAL = 1` 로 1.25초를 확보했습니다. 추가 단축에는 모델 경량화가 필요합니다.
- **회귀 테스트 fixture 가 없습니다.** 검증은 합성 프레임(`selftest.py`) 25항목뿐이고,
  녹화 영상 기반 회귀 세트(역광 / 야간 블루밍 / 점멸 구간)는 없습니다.
- **녹색 점멸을 분류기가 구분하지 못합니다.** 학습 라벨에 없어 켜짐/꺼짐 전환 횟수로만 추정합니다.
- **점자블록은 색 기반입니다.** 텍스처 검증과 IPM 이 미구현이라 노란 물체 오탐을 걸러내지 못합니다.
- **거리 추정은 8m 까지만 신뢰합니다.** 그 너머는 안내에서 제외합니다.
