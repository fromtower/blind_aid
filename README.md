# blind_aid

## 파일 구성

### 실행 진입점

**`main.py`** — 통합 루프
전체 파이프라인을 묶는 곳. 프레임을 받아서 조도 프로파일 판정 → 신호등 → 점자블록 → 장애물 순으로 돌리고, 결과를 음성 안내 큐에 넣는다. `--source`로 파이 카메라/동영상 전환, `--no-detect`로 YOLO 없이 색 로직만, `--view`로 디버그 화면. 새 기능은 대체로 여기가 아니라 각 모듈에 넣고 여기서는 호출만 추가한다.

**`check_camera.py`** — 카메라 1차 진단
파이에 처음 올렸을 때 제일 먼저 돌리는 스크립트. 다른 파일에 의존하지 않아 이것만 복사해도 동작한다. picamera2 임포트, 센서 지원 모드, 듀얼 스트림 구성, 실측 fps, 채널 순서, 조도 메타데이터를 순서대로 확인한다. **채널 순서 확인이 가장 중요하다** — picamera2의 `RGB888`은 이름과 달리 BGR로 들어오는 경우가 있고, 뒤집혀 있으면 빨간불과 초록불이 서로 바뀐다.

**`calibrate.py`** — 거리 추정 캘리브레이션
`FOCAL_PX`를 실측한다. 키를 아는 사람이 정확히 5m 떨어져 서고, 스페이스바로 샘플을 여러 번 모으면 중앙값을 출력한다. **이걸 안 하면 모든 거리 안내가 틀린다.** 스트림 해상도를 바꾸면 다시 측정해야 한다.

**`selftest.py`** — 하드웨어 없이 로직 검증
합성 프레임(회색 아스팔트 + 황색 띠, 어두운 배경 + 적/녹 원)을 만들어 색 판정 모듈을 검사한다. 총 17개 테스트. 카메라도 파이도 없이 돌아가므로, 코드 고칠 때마다 이걸 먼저 돌려서 깨진 데가 없는지 본다. 실기 튜닝을 대체하지는 못한다.

### 설정

**`config.py`** — 모든 튜닝 상수
스트림 해상도, 거리 임계값, 색공간 임계값, 음성 쿨다운이 전부 여기 모여 있다. **다른 파일에 숫자를 직접 박지 말 것.** 현장에서 노트북 열고 이 파일만 고치면 되도록 의도한 구조다. 왜 그 값인지 주석으로 근거를 남겨두었다.

### 입력

**`sources.py`** — 프레임 소스 추상화
파이에서는 Picamera2 듀얼 스트림, 개발 PC에서는 동영상 파일이나 웹캠을 같은 인터페이스로 제공한다. 덕분에 `main.py`는 어디서 돌든 코드가 같다. main(고해상도, ROI 크롭 전용)과 lores(416, 신경망 입력)를 함께 내보낸다.

### 인식 모듈

**`pavement.py`** — 점자블록 검출 (학습 없음)
LAB 색공간의 b\* 채널로 황색 유도블록을 찾고, 최소외접사각형으로 진행 방향과 좌우 편차를 구한다. HSV 대신 LAB을 쓰는 이유는 b\*가 밝기와 분리된 축이라 역광·그늘·박명에서 덜 흔들리기 때문이다. 연속 미검출을 세어 "블록을 벗어났습니다" 판정도 한다.

**`signal_light.py`** — 보행 신호등 판정 (학습 없음)
MAIN 스트림 상단 ROI를 **원본 해상도로** 크롭해 처리한다. 20m 거리의 보행등은 416으로 줄이면 6px이 되어 색 판정이 불가능하기 때문이다. 밝기 게이트 → 원형도/종횡비 필터 → LAB a\* 분류 순으로 후보를 걸러내고, 단일 프레임이 아닌 5프레임 투표로 확정한다. 켜짐/꺼짐 전환 횟수로 녹색 점멸(곧 바뀜)도 검출한다.

**`detect.py`** — 장애물 검출 + 거리 추정
COCO 사전학습 YOLO를 그대로 쓴다(학습 데이터 0장). ByteTrack으로 추적하고, bbox 높이에서 단안 거리를 추정한 뒤 시계열 기울기로 접근 속도를 낸다. 8m를 넘으면 신뢰하지 않고 안내에서 제외한다.

**`context.py`** — 조도 프로파일 판정
BH1750 조도센서가 있으면 그 값을, 없으면 카메라의 AnalogueGain을 프록시로 써서 day/dusk/night를 판정한다. 센서가 없어도 동작한다. 경계에서 프로파일이 깜빡이지 않도록 히스테리시스를 걸어두었다.

### 출력

**`announce.py`** — 음성 안내
우선순위 큐와 종류별 쿨다운으로 발화량을 제어한다. 시각장애인 보조에서 가장 흔한 실패는 인식 실패가 아니라 **말이 너무 많은 것**이다. 계속 떠들면 사용자가 흰지팡이와 주변 소리에 집중하지 못해 오히려 위험해진다. 재생은 별도 스레드에서 하므로 메인 루프를 막지 않는다.
